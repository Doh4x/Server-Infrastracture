## Установка

```bash
sudo git clone https://github.com/doh4x/server-infra.git /srv/infra
sudo bash /srv/infra/setup.sh
```

## Развернуть приложение

```bash
app deploy https://github.com/<вы>/blog.git
```

Команда склонирует репозиторий в `/srv/apps/<имя>` и задаст несколько вопросов:

- имя приложения (по умолчанию — имя репозитория);
- какой compose-файл запускать, если их несколько (`compose.prod.yaml` предлагается первым);
- значения из `.env.example`, если он есть;
- какой сервис смотрит в интернет и на каком порту он слушает внутри контейнера;
- домен.

Задать вопросы заново (поменять домен, порт, настройки): `app setup <имя>`.

Имя можно передать сразу (`app deploy <url> blog`), тогда команда его не спрашивает.

## Команды

| Что | Команда |
|---|---|
| Развернуть из git | `app deploy <url> [имя]` |
| Список приложений, сколько контейнеров работает, домены | `app list` |
| Обновить: `git pull`, свежие образы, перезапуск | `app update <имя>` |
| Обновить все приложения | `app update --all` |
| Обновить, оставив свои правки в файлах приложения поверх новой версии | `app update <имя> --keep` |
| Обновить, выбросив свои правки | `app update <имя> --discard` |
| Обновить саму инфраструктуру: `git pull` этого репозитория и `setup.sh` заново | `app self-update` |
| Войти в ghcr.io для закрытых образов | `app login` |
| В какие реестры вошёл сервер и под каким логином | `app logins` |
| Выйти из реестра (например, чтобы войти под другим аккаунтом) | `app logout [реестр]` |
| Логи | `app logs <имя> [сервис]` |
| Контейнеры приложения | `app status <имя>` |
| Перезапустить, остановить, запустить. `restart` пересоздаёт контейнеры, поэтому подхватывает правки в `.env` | `app restart <имя>`, `app stop <имя>`, `app start <имя>` |
| Удалить приложение вместе с доменами | `app remove <имя>` |
| Какие домены куда ведут | `site list` |
| Сколько памяти и процессора ест | `docker stats` |
| Логи прокси (сертификаты, ошибки 502) | `site logs` |
| Перезапустить прокси | `site restart` |
| Установленные сертификаты Cloudflare | `site cert` |
| Сколько места занимает Docker | `docker system df` |

## Что должно быть в репозитории приложения

- `compose.yaml` или `compose.prod.yaml`;
- `.env.example` с настройками, если они нужны (пароли в git не кладутся);
- на слабом сервере лучше готовые образы (`image:`), собранные в GitHub Actions, а не сборка (`build:`) на месте.

## Вручную, без мастера

Приложение — это папка в `/srv/apps` со своим `compose.yaml`. Сервис, который должен быть доступен снаружи, подключается к сети `proxy` под уникальным именем:

```yaml
services:
  app:
    image: ghcr.io/<вы>/blog:latest
    restart: unless-stopped
    networks:
      default:
      proxy:
        aliases:
          - blog

networks:
  proxy:
    external: true
```

```bash
docker compose up -d
site add blog.example.ru blog:3000
```
